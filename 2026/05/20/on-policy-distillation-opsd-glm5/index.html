从 KD 到 OPSD：On-Policy 蒸馏技术演进与 GLM-5 实践解读

大模型后训练（post-training）正在从”SFT + RLHF”的两阶段范式，演进到以 On-Policy Distillation (OPD) 为核心的新范式。本文梳理蒸馏技术从离线 KD 到 OPSD 的演进脉络，解读 OPSD 论文的核心机制，并结合 GLM-5 技术报告分析 OPD 在大规模生产中的实践。

2. OPD：On-Policy Distillation

2.1 原理

OPD (Agarwal et al., ICLR 2024) 的核心思想：

  1. Student 从自己的 policy 采样 rollout
  2. Teacher 在 student 生成的每个状态上给出 logprobs
  3. Student 学习匹配 teacher 在这些状态上的分布

形式化定义：

其中 $\pi_\theta$ 是 student，$\nu$ 是 teacher，$s_t = (x, y_{<t})$ 是 student 自己走到的状态。

2.2 两种 Loss 变体

GKD OPD（forward KL，需要 teacher 完整分布）：

直接通过 student 概率反向传播。使用 teacher 的 full distributional signal，精度高但显存开销大。

PG OPD（reverse KL 的单样本估计，只需 teacher 的一个 logprob）：

把 teacher 和 student 的 log probability 之差作为 per-token reward，通过 policy gradient 更新。stop-gradient 是必须的——否则梯度会忽略 teacher 信号。

2.3 Forward KL vs Reverse KL

给定 Teacher 分布 $\nu$ 和 Student 分布 $\pi_\theta$，有两个方向的 KL：

Forward KL（Teacher 视角，”Teacher 觉得 Student 差在哪”）：

  • 由 Teacher 分布 $\nu$ 加权
  • Teacher 认为重要的 token（$\nu$ 大的），如果 Student 概率低 → 惩罚大
  • Mode-covering：Student 被鼓励覆盖 Teacher 的所有模式
  • 需要 Teacher 的完整 top-k 分布（GKD OPD 用这个）

Reverse KL（Student 视角，”Student 和 Teacher 差多少”）：

  • 由 Student 分布 $\pi_\theta$ 加权
  • Student 自己概率高的 token，如果 Teacher 概率低 → 惩罚大
  • Mode-seeking：Student 集中学 Teacher 最强的模式，放弃弱模式
  • 可以用单样本估计（只需要 Teacher 在采样 token 上的一个 logprob）

为什么 PG OPD 用 Reverse KL：Student 采样一个 $y_t \sim \pi_\theta$，就能得到 reverse KL 的无偏单样本估计：

Forward KL 做不到这一点——它需要 $\nu$ 的完整分布才能计算。

2.4 veRL 的 Reverse KL 估计器

定义 importance ratio：$\rho_t = \frac{\nu(y_t|s_t)}{\pi_\theta(y_t|s_t)}$

所有估计器都是 $\rho$ 的函数：

k1（Log-ratio）：$D_{k1}(\rho) = \log \rho$

  • reverse KL 的直接单样本估计，无偏
  • 问题：$\rho \to 0$ 时 $\log \rho \to -\infty$（梯度爆炸）
  • 用途：GLM-5、OPSD 论文

k2（Chi-squared）：$D_{k2}(\rho) = \frac{1}{2}(\rho - 1)^2$

  • $\chi^2$ 散度估计，对称
  • 问题：$\rho$ 很大时惩罚 $O(\rho^2)$

k3（Pinsker 风格，veRL 默认）：$D_{k3}(\rho) = \rho - 1 - \log \rho$

  • 永远非负，稳定性最好
  • $\rho \to 0$ 时不像 k1 那样爆炸，$\rho \to \infty$ 时线性增长（不像 k2 平方增长）
  • 来源：DeepSeek-V4 采用

数值对比：

$\rho$ 含义 k1 k2 k3
0.01 Student 极不对 -4.61 0.49 3.62
0.1 Student 不太对 -2.30 0.41 1.40
0.5 Student 偏弱 -0.69 0.13 0.19
1.0 完美一致 0 0 0
2.0 Teacher 更强 0.69 0.50 0.31
10.0 差异极大 2.30 40.50 6.70

如何选择：

场景 推荐 原因
通用 OPD k3 稳定，DeepSeek-V4 验证
数学推理（答案确定性高） k1 或 k3 k1 更简单，但需要 clipping
搜索 Agent（答案开放性高） k3 Teacher/Student 分布可能差异大，k3 更稳定
需要完整分布信号 forward_kl_topk GKD 模式，精度最高但贵

2.5 Forward KL Top-K（GKD OPD）

与单样本估计器完全不同——使用 Teacher 的完整 top-k 分布：

  • 需要 Teacher 返回 top-k 个 token 的概率（默认 k=32）
  • 直接对 Student 概率反向传播（不走 policy gradient）
  • 信号最 dense（每个位置有 k 个 token 的分布信息）
  • 显存开销大（需要存 k × sequence_length 的 logit tensor）

OPSD 论文实验表明 Forward KL > Reverse KL（Table 3），但 GLM-5 在生产中选了 PG OPD (k1)，因为长 trajectory 的显存开销不允许 forward KL。

2.6 Multi-Teacher OPD (MOPD)

多个领域专家 teacher 同时蒸馏到一个 student。每个训练样本通过 teacher_key 路由到对应的 teacher。

已在生产中使用：GLM-5、Qwen3、Nemotron-Cascade 2、MiMo-v2-flash、DeepSeek-V4。

2.7 veRL 的 OPD 实现

veRL 已有完整的 OPD 实现（文档），支持：

参数 说明
loss_mode k3（默认）、k1、forward_kl_topk 等
use_task_rewards 是否叠加 RL reward（默认 true）
distillation_loss_coef 蒸馏 loss 权重（默认 1.0）
loss_max_clamp per-token loss 截断
多 Teacher 支持，通过 teacher_models 配置

3. OPSD：On-Policy Self-Distillation

论文：arXiv:2601.18734 (Siyan Zhao et al., UCLA + Meta, ICML 2026)
代码：https://github.com/siyan-zhao/OPSD

3.1 核心机制

同一个模型，不同的输入，分别扮演 Student 和 Teacher：

直觉：rationalization（知道答案后理解推理步骤）比 generation（从零推理）容易得多。给模型看正确答案后，它在 student 走过的每个状态上都能提供更好的 token 分布。

3.2 算法流程

3.3 Prompt 构造

Teacher 的 prompt 里包含正确答案 y*，但它不生成任何 token——只对 student 的 rollout ŷ 做一次 forward pass，算出每个位置的 logprobs。

3.4 关键设计决策

Teacher 固定为初始 checkpoint：训练过程中不更新 teacher 权重。这样做的好处：

  • 稳定训练
  • 隐式正则化：防止 student 偏离初始 policy 太远（类似 GRPO/PPO 中对 reference policy 的 KL penalty）

Thinking Mode 选择（Qwen3 场景）：

  • 最佳组合：Student TM-off + Teacher TM-on
  • 原因：Teacher 开 thinking 后，在数学相关 token 上的 KL 差异最大 → 监督信号最强

Per-Token Pointwise KL Clipping：

  • 问题：stylistic tokens（”wait”、”however”、”therefore”）的 KL divergence 远高于数学 tokens，会主导训练信号

  • 效果：防止性能崩塌，尤其在 OPSD 快速收敛（~100 steps）时尤为重要

3.5 核心实验结果

在竞赛级数学推理 benchmark 上：

方法 Token 预算/题 Rollouts/题 收敛步数
GRPO ~128K tokens (8×16K) 8 ~500
OPSD ~1K tokens 1 ~100
SFT ~1K tokens - ~200

OPSD 的 token 效率比 GRPO 高 128 倍，同时效果相当或更好。

GRPO 的问题：在 100 步内，>50% 的 batch 出现 reward diversity collapse（全对或全错），梯度信号为零。OPSD 的 dense token-level loss 完全不受此影响——答对答错都有学习信号。

SFT 的问题：在 OpenThoughts 数据集上，SFT 后模型生成长度缩短（学了简洁的参考答案的风格），反而降低了竞赛数学的表现。

3.6 Policy Gradient 视角

OPSD 可以被看作一个 dense token-level reward 的 policy gradient：

这个 per-token reward 衡量的是”知道答案的模型在这个 token 上比不知道的模型更倾向于什么”。和 STaR 的对比：

  • STaR：sequence-level binary reward（全对才有梯度）
  • OPSD：token-level dense reward（每个 token 都有梯度，即使最终答案错误）

模型：744B 总参数 / 40B 激活参数，256 experts MoE，DSA (Dynamic Sparse Attention)

4.1 五阶段后训练 Pipeline

4.2 Stage 5：跨阶段 OPD

目的：恢复前序阶段被后续 RL 退化的能力。

每个 RL 阶段（Reasoning → Agentic → General）都会优化特定能力，但可能损伤其他能力（catastrophic forgetting）。Stage 5 用 OPD 从各阶段最佳 checkpoint 蒸馏回来。

实现：PG OPD formulation

  • Teacher = 前序阶段的 final checkpoint
  • GRPO group_size = 1（advantage 来自 teacher log-ratio，不需要 group 内对比）
  • 支持 Multi-Teacher（Reasoning teacher + General teacher 混合路由）

4.3 异步 RL 基础设施 (SLIME)

GLM-5 的 RL 训练基于 SLIME 框架（https://github.com/THUDM/slime），核心优化：

异步训练：generation 和 training 解耦。关键公式：

通过 pop(ρ, 1/β, β) 过滤偏离太远的样本（β=2），保证 off-policy 修正的稳定性。

尾延迟优化：

  • No-queue serving：EP64 + DP64 跨 8 节点，足够 KV-cache 避免排队
  • FP8 rollouts + MTP：减少 per-token 延迟
  • PD 分离（Prefill-Decode Disaggregation）：prefill 和 decode 分离到不同节点

Thinking Mode 创新（三种模式统一）：

  1. Always-on thinking：标准 CoT 推理
  2. Always-off thinking：直接回答，低延迟
  3. Interleaved Thinking：turn-level 控制——简单请求关闭 thinking，复杂任务开启 thinking，同一个 session 内动态调整

4.4 Agentic RL（Stage 3）

GLM-5 的 agentic RL 覆盖：前后端编程、工具调用、搜索 agent、通用 agent。

核心特点：

  • 异步 GRPO 在完整的多轮 trajectory 上训练
  • 支持工具调用和环境反馈
  • Benchmark：SWE-bench Verified, Terminal-Bench 2.0, BrowseComp, MCP-Atlas, τ²-Bench

5. 对搜索 Agent 的启示

5.1 OPSD 在搜索 Agent 场景的适配

OPSD 论文在数学推理上验证，搜索 agent 场景有几个关键差异：

差异点 数学推理 搜索 Agent
答案确定性 唯一正确答案 开放式文本
Trajectory 长度 ~1K tokens 5K-10K tokens（含 tool results）
外部交互 无 搜索调用、网页抓取
GT 来源 数学验证器 强模型（如 Claude）产出

适配方案：

Loss mask：只在 assistant 部分（think + tool_call + answer）算 loss，跳过 tool_result（外部返回的搜索结果不是模型生成的）。

5.2 开放问题

  1. 长 trajectory 的有效性：论文说早期 token 更重要（关键分支点），search agent 的第一次 search query 选择是否也是关键分支点？
  2. 开放式答案的 rationalization 质量：数学答案是唯一的，Teacher rationalization 精准。搜索答案是开放的，Teacher 能否有效 rationalize？
  3. Teacher 过期：OPSD 固定 teacher 为初始 checkpoint。如果模型快速学会新工具，初始 teacher 可能给出过时指导。何时刷新？
  4. 全词表 vs 采样 token：论文推荐全词表 logit 蒸馏，但长 trajectory 的显存开销可能不可接受。GLM-5 在生产中选择了 PG OPD（采样 token）正是因为这个 trade-off。
